# 商户工作台的开店指引

店长第一次进入工作台，往往不清楚这套系统在店里怎么运转、钱从哪来、玩家会经历什么，也不知道要配哪些东西才能真正营业。「开店指引」页签从店家和玩家两个视角讲清楚"正常营业是什么样"，再按店铺的经营方式列出接入步骤，并根据现有接口判断每一步是否已完成。

实现见 `packages/prism-web/src/ui/merchant/ShopGuide.tsx`（页面与加载）、`setup-guide.ts`（纯推导，测试在 `setup-guide.test.ts`）和 `BillingExplainer.tsx`（计费图解）。

## 经营方式

不单独存字段，由现有设置推出（`operatingMode`）：

| 经营方式 | 判定 | 含义 |
| --- | --- | --- |
| 不使用计费（`devices`） | 没有任何资源组或资源设置计费方案 | 只用 PRiSM 的设备功能，收费在店家自己的其它经营平台完成 |
| 自助计费，无前台（`self`） | 有资源计费、未开前台收银 | 玩家在手机上入场、自助结账，从预存余额扣款；常见于无人值守、在线上群里运营的店。即使有店员，店员也不负责收钱 |
| 前台收银（`desk`） | 有资源计费、开启前台收银 | 有前台的店一定在前台收钱：玩家刷实体卡入场，离店时现场付款；带手机的玩家也可以自助 |

「有资源计费」由 `shopBills` 判断：任一资源组（默认资源组的方案即店铺默认计费方案）或资源专属方案已设置。这只是描述，不是开关——店铺没有整店计费开关。建店向导第一步就是这三选一（「店里怎么收费？」）；「不使用计费」只是不创建方案，之后给资源组设置方案即开始计费，前台收银在「设置 → 营业与计费」切换。选前台收银时，`POST /api/v1/merchant/shops` 的 `billingSetup.cashierEnabled: true` 会同时开启前台收银。

## 何时出现、默认落点

- 只对店长（owner）显示。
- 有未完成步骤时，「开店指引」排在页签最前，`/merchant/:shop` 默认跳到 `/merchant/:shop/guide`；全部完成后页签消失，默认进入「在店」，设置页标题右侧保留入口。
- 新建店铺的向导结束后直接进入指引。

## 页面结构

1. **经营方式**：当前方式及一句话说明，附「更改」链接。
2. **正常营业时，玩家这样用**：按经营方式画出玩家的一次到店。
   - 自助：碰 NFC 或扫码 → 登录 →（要求绑定时）第一次来绑定身份 → 确认计费规则（这台资源今天的计费规则与封顶进度；换到别的资源时说明要新增、保留或结束哪些计费）→ 用设备 → 离店结账。
   - 前台：前台刷卡 → 店员点入场（按默认计费方案计时）→ 游玩 → 回前台付款；并说明带手机的玩家也可以自助。
   - 不计费：碰 NFC 或扫码 → 登录 →（门锁要求绑定时）绑定身份 → 操作设备。
3. **你每天在后台做什么**：按经营方式列出各页签在日常里的用途。
4. **钱从哪来、怎么扣**（有资源计费时）：系统没有接入在线支付，余额只来自兑换码（店家在任何渠道售卖）、店员充值、礼物与活动；结账先扣赠送余额、再扣充值余额，余额不够结不了账、计时继续，店员可「充值结账」。前台模式在最前面说明现场收款不进余额，系统只记录金额、收款方式和收银员。
5. **计费是怎么算的**（有资源计费时）：打开图解弹窗，计费页也有同一入口，见下文。
6. **接入步骤**。
7. **按需配置**：接入 Bot、邀请店员（非前台）、新玩家礼物（拉新，不是付款方式）、优惠与活动、开启前台收银（自助店）或改用 PRiSM 计费（还没有资源计费时）、到店位置校验、从 prism-neo 迁移。

## 接入步骤与完成判定

| 步骤 | 出现条件 | 完成条件 |
| --- | --- | --- |
| 设定收费标准 | 有资源计费 | 有有效余额资产，且默认计费方案（若已设置）仍有效；未就绪时区分余额资产缺失（去「资产」恢复）与默认计费方案失效（去「资源」页编辑默认资源组）。默认资源组不设方案（免费）不算未完成 |
| 准备前台读卡器 | 前台收银 | 本浏览器已授权 HINATA 读卡器（WebHID `getDevices()` 中有 vendor `0xF822`）；浏览器不支持 WebHID 时提示用桌面版 Chrome 或 Edge |
| 给前台店员开账号 | 前台收银 | 店铺成员多于 1 人；说明在前台收款需要计费权限「管理」 |
| 确认玩家身份与 Bot | 有资源计费；或有门锁、麻将设备 | 不要求绑定；或有效的 Bot 凭据 `lastUsedAt` 非空。步骤内可直接改身份策略，并预览当前的绑定提示 |
| 准备玩家储值 | 自助计费 | 有可用兑换码（未用尽、未过期），或已有玩家余额大于 0 |
| 添加资源并配置能力 | 总是 | 至少一个资源且都配置了能力；没有能力的资源只用来开始计费 |
| 连接 TTLock 账号 | 有资源启用开门密码 | `ttLockConnection` 有 `clientId`、`clientSecret` 及 `accessToken` 或 `appAccount` |
| 贴好二维码或 NFC，自己试一次 | 总是 | 有资源计费且已有玩家档案；或店长勾选「我已试过」（`localStorage` 的 `prism.setup.trial.<shopCode>`） |

数据来源全部是现有 GET 接口：`settings`、`merchant/machines`、`merchant/resource-groups`、`staff/settings`、`staff/api-tokens`、`staff/players`、`merchant/shop-members`、`staff/presents`、`staff/redeem-codes`。可选数据读取失败只让对应步骤按未完成显示，不阻塞工作台。

## 玩家身份

`IdentityPolicyPicker.tsx` 在指引和「设置 → 玩家与身份」共用，两个选项，绑定在前：

- **要求绑定平台身份（推荐）**：玩家第一次进店前把绑定码发给店铺 Bot。店家因此知道每位玩家的 QQ 号等身份；Bot 只在店铺群里响应时，只有群成员能进店。其下的高级勾选项「只允许已有档案的玩家绑定」（`autoRegister: false`）只用于迁移来的店，任何情况下都不作为默认值。
- **登录网页账号即可**：不需要 Bot，店家只知道玩家的 PRiSM 账号。

新店铺默认要求绑定并自动建档（含没有资源计费的店铺）。绑定提示、Bot 向玩家开放哪些命令见 [integrations-and-machines.md](integrations-and-machines.md) 的 Integration 一节。

## 计费图解

`BillingExplainer` 用一个连贯的例子画四张图，数字与计费引擎一致（[billing-flow.md](billing-flow.md)）：

规则说明里写明：新建的规则要成为资源组的默认计费方案、资源自己的方案，或被其他规则「依赖」才会计费；时段封顶填 0 表示不封顶；消费封顶合计所有按时计费的规则，两种封顶同时生效时按实际收取的金额一起算，每个单位只少收一次。

1. **按单位计费、宽限内不进位**：每 30 分钟 10 元、宽限 5 分钟的阶梯图，35 分钟 10 元、36 分钟 20 元；开场宽限只在没操作设备时免单。
2. **跨时段分别计算、时段封顶只管本时段**：日场 12 元/小时封顶 40、夜场 8 元/小时，14:00–20:30 共 64 元的累计曲线；并说明入场锁定规则版本。
3. **多条计费与消费封顶**：入场 64 元 + 麻将 30 元，全天消费封顶 80 元（消费封顶不再选适用规则，覆盖所有按时计费的规则）。
4. **结账扣款顺序**：94 → 消费封顶 −14 → 优惠券 −6 → 应付 74，先扣赠送余额 20、再扣充值余额 54。

末尾链接到计费页的计费模拟器（`/merchant/:shop/pricing?simulate=1` 直接展开），用本店规则试算。

## 资源入口：二维码与 NFC

二维码和 NFC 是同一个链接 `/t/:shop/:resource`。玩家打开后，设置了计费方案的资源先显示「计费规则」卡片（各方案今天的时段、跨方案封顶的进度和已计金额），确认后才开始计费；机台读卡器支持时，玩家还能在选卡区点「+」，把卡放到这台机器的读卡器上直接添加。NFC 标签写入 NDEF URI 记录即可；iPhone 碰一下唤起 hinata_go 里的 PRiSM Link App Clip（免安装），其它手机用浏览器或 HINATA Go 打开。资源二维码弹窗提供打印、复制链接，并写明 NFC 的写法。
