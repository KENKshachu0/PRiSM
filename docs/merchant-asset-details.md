# 商户后台物品详情

店铺后台「资产与兑换」使用现有员工 API 返回的数据，提供列表摘要与只读详情。子页签写在 URL 的 `tab` 参数（`effects`、`gifts`、`codes`，资产为默认），其他页面可直接链接。各子页签为空时说明该对象的用途并给出新建按钮；没有可用礼物时，兑换码页引导先创建礼物。新建资产时的 `coupon` 类型与列表统一称为「优惠券」。详情按钮向有查看权限的店员开放，不要求写权限；添加、编辑、归档、恢复和撤销仍按原写权限控制。

## 资产

列表显示名称、具体类型、数量是否可叠加、对玩家隐藏状态、关联优惠、定义有效期及归档／未生效／已过期状态。旧的 `pass`、`ticket` 分别显示为通行证、票券，自定义类型保留其原标识，不统一掩盖为“权益”。

详情显示资产编号、玩家可见性、系统资产标志、说明，以及关联优惠的完整条件。扩展 metadata 放在折叠的「其他保存信息」中，保留旧系统导入和自定义属性的可查阅性，不参与新增收费计算。

物品定义的有效期与玩家持有记录的有效期是两个层级；此处展示的是定义配置，不代表某位玩家的持有数量或最终可消费状态。

## 优惠

列表显示具体优惠金额或比例、作用范围、是否消耗、每日使用上限及有效期状态。详情补齐优惠编号、生效／到期时间、最低消费、适用计时、计费方案与规则，以及适用日期和星期。

关联方案、规则优先解析为名称；名称无法加载或引用不存在时保留保存的编号，不将限制误显示成“不限”。关联资产优先使用优惠列表中的最新配置，列表尚未返回时可使用资产 API 附带的优惠对象。

业务的比例值表示减免百分比，例如保存的 `20` 表示减免 20%，不是支付 20% 或减免 0.2%。输入提示改为 `0～100`，查看时显示 `减免 20%`，不修改旧保存值或计算规则。优惠扩展配置原文可在折叠信息中查看。

## 礼物与兑换码

礼物列表显示发放内容、每位玩家是否限领一次与状态。详情同时显示礼物本身有效期，以及每项资产的类型、编号、数量、叠加／延长／替换方式、内容有效期和延长时长。

兑换码详情显示编号、使用上限与剩余次数、生效／到期时间、关联礼物的上述条件以及兑换人／兑换时间。兑换码、礼物和内容有效期分别展示，不能只用兑换码有效期代表所有发放条件。

## 时间与保存

所有绝对日期时间按店铺展示时区格式化，包括旧的 Z 格式响应；读取和展示不会改变保存的时间点。优惠日期／星期是 UTC 计费日条件，标为「适用日期（UTC）」「适用星期（UTC）」，不将裸日历条件当成绝对事件重新偏移。

查看详情不发送写请求。现有编辑保存继续带回未编辑的有效期、metadata 和优惠 config。当前绑定的已归档优惠在资产编辑选项中保留并标注，避免打开编辑器后被浏览器自动选成“无”；后端仍按原规则要求先恢复或明确换绑，不能借详情页面绕过归档限制。已归档资产与优惠需先恢复，再编辑。

此次只补 UI 展示、前端字段类型与文案，没有新增 API 字段或数据库迁移。
