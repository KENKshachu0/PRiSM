# 计费整数与单位约定

计费计算、余额、账单、流水和持久化采用整数，不采用所有资产统一乘 100 的标度。

| 数据 | 计算／存储单位 | 对外 API 单位 | 示例 |
|---|---|---|---|
| 金额、货币余额、价格、折扣金额 | 分 | 元 | 12.34 元存 `1234` |
| 券、票及其他计数资产 | 自然整数个数 | 自然整数个数 | 2 张存 `2` |
| 百分比折扣 | 整数基点（1/100 百分点） | 百分数 | 12.34% 存 `1234` |
| 时间参数 | 原有分钟／毫秒 | 原有单位 | 不随金额缩放 |

## 边界

- HTTP 入参与定价配置对象仍使用自然单位，兼容现有客户端；进入金额计算时调用 `centsOf(元)`。
- `centsOf` 解析输入 number 的十进制表示，用 BigInt 缩放，半分向远离零的方向舍入：`1.005 → 101`、`-1.005 → -101`。非有限数和安全整数范围外的结果拒绝进入计费。
- `centsOfInteger(分)` 只接收已有整数，不做单位换算。SQL 读到的小数是错误，不再以容差掩盖。
- `assetQuantityOf(assetType, quantity)` 对 currency 转分，对其他资产验证自然整数；小数张数直接拒绝。输出用 `assetQuantityToNatural`。
- `yuanOf` 只在展示／HTTP 输出边界恢复元。API 的 JSON number 不是参与下一步计费的内部中间值。
- 货币数量使用 `Cents`，券票及其他计数资产使用 `Units`。异构列表使用二者的联合类型；货币求和前先按 `assetType` 收窄。`assetQuantityFromStored` 按资产类型恢复品牌，不改变数据库数值。
- 按 holdingId 调整资产时，输入的资产类型和代码必须与持有记录一致，避免用错误单位调整余额或写入错类流水。

## 计算

金额字段使用 `Cents`，包括费用项、调整项、会话结算、玩家结账和已支付历史。合计在整数域完成，不能先转元再相加。

- 加减与求和使用 `addCents`、`subCents`、`sumCents`，检查安全整数溢出。
- 比较使用整数直接比较或 `compareCents`，不使用浮点容差。
- 比例运算使用 `mulDivRound(value, numerator, denominator, mode)`：BigInt 中间乘积，调用处明确舍入方向。
- 分摊使用 `allocate(total, weights)`：最大余数法，各项之和严格等于原总额。
- 时间封顶按重叠毫秒分摊时，未覆盖区间也占权重，避免把整笔费用错误计入封顶窗口。
- 跨会话封顶只把折扣分配给正费用，保留负费用的原值与总额守恒。
- 百分比先量化为整数基点，再以 `10000` 为分母计算折扣。

`quantizeMoney` 用于自然单位配置入口的两位小数量化；负价格在量化前拒绝，不能因舍入变成零而通过验证。效果值（包括百分比）和最低消费门槛在保存返回时即与存储精度一致。已删除旧浮点容差工具及未使用的计数运算封装。

## 存储

迁移 `0022_integer_money_columns.sql` 将 11 张表中的 13 个数值列改为 INTEGER，并添加 `typeof(...)=integer` 约束：资产余额／流水、结算与结账、费用项／调整项、定价与封顶历史、效果值、服务项目与订单价格。

配置 JSON 的计费值也存整数：

- `pricing_configs.provider_json`：固定费用、单位价格、封顶价格、paidHistory。
- `pricing_effects`：金额值按分，百分比按基点；`config_json.minSubtotal` 按分。
- `presents.grants_json`：currency 的 amount 按分，券票的 amount 按自然整数。

存储编解码集中在 `storage-sql`。定价配置／礼包的领域对象仍采用自然单位，经统一序列化器入库；旧系统导入也使用相同序列化器。不要直接把 API JSON 写入这些列。

历史 `metadata_json`、审计上下文是原始记录，不作为金额计算来源，不做无结构的全局数字乘 100。

## 升级与回滚

1. 核对目标 Worker、D1、域名，备份目标数据库；禁止把生产配置误用于 beta。
2. 暂停旧 Worker 的访问与写入，等待在途请求结束。旧代码与新数据库单位不兼容。
3. 执行 0022 并部署对应新代码。迁移使用延迟外键检查并恢复索引；一次性运行，不能再次手动执行放大。
4. 验证所有计费列均为 integer、券票数量不变、金额逐行按分一致、外键检查无异常，再恢复访问。
5. 回滚必须协调恢复数据库与对应旧代码，不能只回滚 Worker。新代码开始接受写入后，需要先保护新增数据。

回归覆盖整数算术、溢出、比例守恒、SQL／D1 适配器、真实 HTTP 自然单位输出，以及旧库迁移、JSON 转换和事务回滚。运行 `bun test` 与 `bun run typecheck`。
